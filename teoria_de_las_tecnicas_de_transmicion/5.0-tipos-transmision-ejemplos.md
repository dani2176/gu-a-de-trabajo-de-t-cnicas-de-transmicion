# 5.0 Tipos de transmisión y ejemplos integradores

## 🟢 Para comenzar

Finalmente se comparan las formas de organizar la transmisión: serie, paralelo, síncrona y asíncrona. Aquí se juntan varios conceptos aprendidos anteriormente y se aplican en situaciones concretas.

La finalidad de esta última sección es que el estudiante pueda pasar de una definición aislada a interpretar un sistema de comunicación completo.

En una transmisión **serie**, los bits se transmiten secuencialmente, uno después de otro.

```text
1 → 0 → 1 → 1 → 0 → 1
```

## 🔎 Para profundizar

En lugar de necesitar una línea independiente para cada bit de una palabra transmitida simultáneamente, una comunicación serie puede enviar los bits siguiendo una secuencia temporal.

```text
TX
 │
 ├── 1 ──────────►
 ├── 0 ──────────►
 ├── 1 ──────────►
 ├── 1 ──────────►
 └── 0 ──────────►
                   RX
```

### 🛰️ Ejemplos

- UART.
- USB.
- Muchos enlaces de datos modernos.

### 🔗 Relación con bit rate

Como los bits aparecen secuencialmente en el tiempo, el bit rate permite indicar cuántos bits se transmiten por segundo.

### 🧮 Ejemplo

A `1 Mbit/s`, idealmente se transmiten:

```text
1.000.000 bits cada segundo
```

### 🎯 Idea clave

> Serie significa que los bits se transmiten de manera secuencial en el tiempo.
## 🧮 Ejemplo

Queremos transmitir:

```text
101101
```

En serie:

```text
1 → 0 → 1 → 1 → 0 → 1
```

La secuencia ocupa diferentes instantes de tiempo.

### 🔗 Relación con reloj

La rapidez con que aparecen los bits depende del sistema de transmisión y de su tasa de símbolos o bits.

### 🛰️ Aplicación

UART es un ejemplo conocido de comunicación serie; USB y muchos enlaces modernos también utilizan transmisión serie.

### 🎯 Para recordar

> Serie significa que la información binaria se organiza secuencialmente en el tiempo.


En una transmisión **paralela**, varios bits pueden transmitirse simultáneamente mediante diferentes líneas.

```text
1 ─────────────►
0 ─────────────►
1 ─────────────►
1 ─────────────►
```

## 🔎 Para profundizar

Si queremos transmitir `1011`, podemos imaginar cuatro líneas:

```text
Línea 1 → 1
Línea 2 → 0
Línea 3 → 1
Línea 4 → 1
```

Los bits se presentan al mismo tiempo en líneas diferentes.

### 🧩 Ventaja y dificultad

La principal idea positiva es que se pueden transportar varios bits simultáneamente. Sin embargo, esto requiere más líneas y puede producir problemas de sincronización entre ellas, especialmente a velocidades y distancias mayores.

### 🎯 Idea clave

> Paralelo significa transmitir varios bits simultáneamente utilizando diferentes líneas.
## 🧮 Ejemplo

Para transmitir:

```text
1011
```

podemos representar:

```text
L1 → 1
L2 → 0
L3 → 1
L4 → 1
```

Los cuatro bits están presentes simultáneamente en cuatro líneas.

### 🔎 Problema de sincronización

Cuando varias líneas recorren físicamente una distancia, sus señales pueden no llegar exactamente al mismo instante. Esta diferencia se denomina **skew** y puede convertirse en un problema a velocidades altas.

### 🎯 Para recordar

> Paralelo puede enviar varios bits al mismo tiempo, pero requiere coordinar múltiples líneas físicas.


La diferencia fundamental está en **cómo se organizan los bits en el tiempo y en el medio físico**.

| Característica | Serie 🔗 | Paralelo 🔗 |
|---|---|---|
| Bits | Uno después de otro | Varios simultáneamente |
| Líneas | Menos | Más |
| Cableado | Más simple | Más complejo |
| Organización | Secuencial | Paralela |

## 🔎 Para profundizar

```text
SERIE
1 → 0 → 1 → 1

PARALELO
1 ─────►
0 ─────►
1 ─────►
1 ─────►
```

La comparación debe hacerse considerando el sistema concreto. “Enviar varios bits al mismo tiempo” no significa automáticamente que un enlace paralelo sea siempre más rápido; la velocidad final depende de la frecuencia, sincronización, pérdidas, diseño y otras limitaciones.

### 🎯 Idea clave

> Serie y paralelo describen la organización de los bits durante la transmisión, no una garantía absoluta de velocidad.
## 🧠 ¿Por qué la comparación no se reduce a “uno vs varios bits”?

También debemos considerar:

- cantidad de conductores;
- sincronización;
- distancia;
- interferencia entre líneas;
- complejidad del hardware.

### 📊 Resumen

| Tema | Serie | Paralelo |
|---|---|---|
| Organización | Secuencial | Simultánea |
| Conductores | Menos | Más |
| Sincronización entre líneas | No aplica de la misma manera | Puede ser crítica |

### 🎯 Para recordar

> La transmisión serie y paralela describen la forma en que se distribuyen los bits durante la transferencia.


En una transmisión **síncrona**, emisor y receptor utilizan una referencia temporal coordinada para interpretar el flujo de datos.

```text
CLOCK
_|¯|_|¯|_|¯|_|¯|_

DATA
_1___0___1___1___
```

## 🔎 Para profundizar

La sincronización permite identificar los momentos relevantes del flujo de datos.

```text
Reloj:
tic   tic   tic   tic

Datos:
 1     0     1     1
```

La forma exacta de sincronización depende del protocolo. Puede existir una señal de reloj compartida o mecanismos equivalentes para mantener el alineamiento temporal.

### 🛰️ Ejemplo conceptual

En un flujo coordinado de datos, el receptor necesita conocer cómo interpretar la posición temporal de los bits o símbolos.

### 🎯 Idea clave

> La transmisión síncrona necesita una coordinación temporal para que emisor y receptor interpreten correctamente el flujo de datos.
## 🧭 Cómo imaginar la sincronización

Supongamos que el receptor sabe que debe leer en los flancos de un reloj:

```text
CLOCK
_|¯|_|¯|_|¯|_|¯|_
     ↑   ↑   ↑

DATA
___1___0___1___
```

La referencia temporal permite determinar cuándo interpretar los datos.

### 🔎 No todos los sistemas síncronos son iguales

Cada protocolo define su propio mecanismo de sincronización. Lo importante para este nivel es comprender que existe una coordinación temporal explícita o equivalente.

### 🎯 Para recordar

> Síncrona significa que el tiempo de interpretación de los datos está coordinado entre los elementos de comunicación.


En una transmisión **asíncrona**, el emisor y el receptor no mantienen un reloj compartido continuamente para todo el flujo. Las unidades de datos pueden incluir elementos que permitan identificar su inicio y término.

```text
┌───────┬──────────────┬───────┐
│ START │     DATOS    │ STOP  │
└───────┴──────────────┴───────┘
```

## 🔎 Para profundizar

El receptor utiliza la estructura de la unidad para saber dónde comienza y termina una transmisión determinada.

### 🛰️ Ejemplo clásico

UART es un ejemplo conocido de comunicación serie asíncrona. Un carácter puede transmitirse con un bit de inicio, bits de datos y uno o más bits de parada, según la configuración.

### 🔗 Relación con velocidad

La comunicación sigue teniendo una tasa temporal, por ejemplo `9600 bit/s` o `115200 bit/s`, pero no por ello se transforma en una comunicación síncrona.

### 🎯 Idea clave

> Asíncrona significa que no se mantiene un reloj compartido continuamente; la unidad de datos contiene información temporal suficiente para ser interpretada.
## 🧩 Ejemplo con UART

Un carácter puede representarse conceptualmente como:

```text
START | DATA | PARIDAD | STOP
```

No todos los sistemas incluyen exactamente los mismos campos; depende de la configuración.

### 🔎 ¿Qué resuelve START?

Permite al receptor identificar que comienza una nueva unidad de datos.

### 🔎 ¿Qué resuelve STOP?

Permite marcar el final de la unidad.

### 🎯 Para recordar

> En una comunicación asíncrona, la delimitación de cada unidad ayuda al receptor a saber cómo interpretar los datos sin mantener un reloj compartido continuamente.


| Característica | Síncrona ⏱️ | Asíncrona 📦 |
|---|---|---|
| Referencia temporal | Coordinada | No compartida continuamente |
| Organización | Flujo coordinado | Unidades delimitadas |
| Reloj | Existe una referencia temporal compartida/coordinada | No se mantiene compartido continuamente |
| Ejemplo | Protocolos con sincronización explícita | UART |

## 🔎 Para profundizar

Una forma sencilla de recordarlo es:

```text
SÍNCRONA
⏱️ Emisor y receptor coordinan el tiempo.

ASÍNCRONA
📦 Cada unidad tiene información que ayuda a delimitarla.
```

La diferencia no significa que una sea “rápida” y la otra “lenta”. Son formas distintas de organizar el tiempo de la comunicación.

### 🎯 Idea clave

> La diferencia fundamental está en cómo se mantiene y utiliza la referencia temporal para interpretar los datos.
## 🧠 Error frecuente

No debemos afirmar:

```text
Síncrona = rápida
Asíncrona = lenta
```

La sincronización y la velocidad son características distintas.

Lo importante es cómo el receptor sabe **cuándo y dónde interpretar los datos**.

### 🎯 Para recordar

```text
Síncrona   → referencia temporal coordinada
Asíncrona  → delimitación/temporización de unidades
```

Estos conceptos suelen confundirse porque todos aparecen en comunicaciones digitales, pero describen cosas diferentes.

```text
🔢 BIT
 ↓
🚦 SÍMBOLO
 ↓
🚦 BAUD
 ↓
📶 BIT RATE
```

## 🔎 Para profundizar

Un **bit** contiene información binaria.

Un **símbolo** es un estado o forma de señal utilizado durante un intervalo determinado.

El **baud** mide símbolos por segundo.

El **bit rate** mide bits por segundo.

Si cada símbolo representa varios bits, entonces:

\[
R_b=R_s\times\log_2(M)
\]

para un sistema ideal con `M` símbolos.

### 🧮 Ejemplo

16 símbolos:

\[
\log_2(16)=4
\]

Por lo tanto, cada símbolo puede representar 4 bits.

Con `500 kbaud`:

\[
500.000\times4=2.000.000bit/s
\]

\[
\boxed{2Mbit/s}
\]

### 🛰️ Relación con QAM

16-QAM utiliza 16 puntos de constelación, por lo que puede asociarse idealmente con 4 bits por símbolo.

### 🎯 Idea clave

> Baud cuenta símbolos; bit rate cuenta bits. La relación entre ambos depende de cuántos bits representa cada símbolo.
## 🧮 Ejemplo integrado

Supongamos un sistema con:

\[
R_s=2Mbaud
\]

Y 8 símbolos posibles.

Entonces:

\[
\log_2(8)=3bits/símbolo
\]

Por lo tanto:

\[
R_b=2M\times3
\]

\[
\boxed{R_b=6Mbit/s}
\]

### 🔗 Cadena completa

```text
8 símbolos
 ↓
3 bits/símbolo
 ↓
2 Mbaud
 ↓
6 Mbit/s
```

Este ejemplo muestra por qué no debemos utilizar “baud” y “bit/s” como si fueran sinónimos.

 ↓

## 🔎 Para profundizar

La voz comienza como una señal acústica. El micrófono convierte la variación acústica en una señal eléctrica. Si el sistema es digital, el ADC toma muestras de esa señal.

Antes del muestreo hay que conocer la banda de frecuencias que interesa conservar. Ese dato permite aplicar Nyquist-Shannon y elegir la frecuencia de muestreo.

Después:

```text
Muestreo
 ↓
Cuantización
 ↓
Codificación
```

produce una secuencia de bits que puede procesarse y transmitirse.

Durante el canal pueden aparecer pérdidas y ruido. La SNR permite cuantificar la relación entre señal y ruido y la teoría de Shannon ayuda a estudiar la capacidad teórica del canal.

### 🎯 Conceptos conectados

```text

→ frecuencia
→ muestreo
→ Nyquist
→ ADC
→ bits
→ bit rate
→ canal
→ ruido
→ SNR
→ Shannon
```

### 🎯 Idea clave

> Una llamada digital reúne casi todos los conceptos de transmisión de señales en una sola cadena.

## 🔎 Relaciones fundamentales

### Frecuencia ↔ período

\[
f=\frac{1}{T}
\]

### Frecuencia ↔ ancho de banda

Las frecuencias de una señal permiten determinar el rango espectral que ocupa.

\[
SNR=\frac{P_s}{P_n}
\]

### SNR ↔ Shannon

\[
C=B\log_2(1+SNR)
\]

### Frecuencia máxima ↔ Nyquist

\[
f_s>2f_{max}
\]

```text

      ↓
    ADC
      ↓

      ↓

```

\[
R_b=R_s\times\log_2(M)
\]

### Modulación ↔ portadora

```text
Información + portadora
          ↓
      Modulación
          ↓
    Señal transmitida
```

## 🧠 Cómo relacionar las cuatro clasificaciones

Hay dos preguntas diferentes:

1. **¿Cómo se organizan físicamente los bits?** → serie o paralelo.
2. **¿Cómo se coordina temporalmente la transmisión?** → síncrona o asíncrona.

Por eso no son categorías que se excluyan entre sí en todos los casos. Un sistema puede ser serie y síncrono o serie y asíncrono.

```text
                 TRANSMISIÓN
                      │
             ┌────────┴────────┐
             │                 │
          Serie/             Síncrona/
          Paralelo           Asíncrona
```

### 🛰️ Ejemplo

Una comunicación UART es un ejemplo conocido de transmisión serie asíncrona, mientras que ciertos enlaces serie pueden trabajar de forma síncrona usando señalización de reloj o recuperación temporal según el sistema.
